# Rules for coding agents

## General

- Write everything in English: code, identifiers, comments, commit messages, docs.
- Keep changes small and focused on the task you were given. Do not refactor unrelated code.
- Every change comes with tests. New behaviour needs new tests; bug fixes need a regression test.
- Run `npm test` before finishing. All tests must pass.
- Do not add paid services, API keys, databases or frameworks (no React, no bundlers). The site is plain static HTML + CSS generated by Node.

## Structure

- `data/schedule.json` — schedule data; the only input of the build.
- `src/` — pure library modules (no file system or network access unless the module's purpose is I/O). Prefer pure functions that take data and return data/strings.
- `scripts/` — thin CLI entry points (`build.js`, `fetch.js`) that wire `src/` modules to the file system / network.
- `public/` — static assets copied as-is into `dist/`.
- `test/` — Vitest tests named `*.test.js`; fixtures under `test/fixtures/`.
- `dist/` — build output, never committed.

## Conventions

- Node.js 20+, ES modules (`import`/`export`), no TypeScript.
- 2-space indentation, single quotes, semicolons.
- Dates in data are ISO strings (`YYYY-MM-DD`); times are optional strings (e.g. `"7:00 PM"`) or `null` when TBA.
- Anything that depends on the current date must accept a `now` parameter so tests are deterministic.
- Always HTML-escape data inserted into generated HTML.
- Tests must never hit the network. Use saved fixtures and injected `fetch` functions.
